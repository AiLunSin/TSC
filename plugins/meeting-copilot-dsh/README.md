# 会议副驾 DSH 插件

在 DSH 会话里用会议副驾：查术语、读卡片、看实时转写、联网检索、要会中提醒。

这些能力都在桌面应用里，插件只负责转过去。所以 Meeting Copilot 必须先在跑；没跑的时候工具会直接说「会议副驾没有在运行」，不会卡在那儿等超时。

插件连的是应用在 `127.0.0.1` 上临时开的端口，令牌每次启动换一个，别的本机进程拿不到就用不了。内容离不离开这台电脑，还是应用自己说了算：配了模型 Key，查义和提醒才会发最小片段；配了检索 Key，联网检索才会出去查。插件本身不新增出网的地方。

左侧栏底部、Settings 上方有个开关。关掉后六个工具从会话里消失，再打开就回来；状态存在 `~/.dsh/meeting-copilot/tools.json`，重启 DSH 后保持。工具关掉不影响开关本身，随时点得开。

## 工具

| 工具 | 作用 |
|---|---|
| `meeting_lookup` | 解释选中的词或短语。没配模型 Key 时只用本机上下文，结果里写明来源 |
| `meeting_cards` | 列出最近卡片，或按 `cardId` 打开详情 |
| `meeting_save_card` | 把一条解释存成卡片，进本机加密库 |
| `meeting_transcript` | 读取当前转写，或开始 / 停止转写、看转写状态 |
| `meeting_web_search` | 用应用里配的博查 / Tavily 检索，受应用的小时限额管着 |
| `meeting_assist` | 看最近转写，给提醒和可以直接说出口的话。要配模型 Key |

左侧栏开关关着的时候，上面六个工具都不注册，模型也看不到。

## 安装

在 DSH 的 Plugins 里选 Add plugin，指向本目录；或者用 `plugin_manager` 的 `install_bundle` 装本目录。装好后新会话就能看到这些工具（当前会话有时也会直接刷出来）。

## 手动验证

应用启动后会在配置目录（`%APPDATA%\com.meetingcopilot.desktop`）写一份 `plugin-bridge.json`，里面是本次运行的端口、令牌和进程号，退出时删掉。插件每次调用都重新读它，所以应用重启不用重装插件。

没有图形界面时，可以用无窗口模式启动应用来验证：

```powershell
$env:MEETING_COPILOT_HEADLESS = '1'
.\meeting-copilot-desktop.exe
```

自动化或便携场景还可以用 `MEETING_COPILOT_BRIDGE_FILE` 指定描述符位置，应用和插件读的是同一个变量（默认在应用配置目录）。

## 已知限制

- 插件不负责启动应用。应用没跑就是「未连接」。
- 转写只在应用进程内存里，应用退出就清空；只有卡片会留下来。
- 卡片详情接口只对当前快照里的草案卡开放，跟桌面端「点开卡片」的行为一样。
- 插件没有自己的界面，结果都在 DSH 会话的工具卡片里。
