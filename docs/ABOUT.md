# 关于会议副驾

会议副驾是一个 Windows 桌面应用。它跟着会议听，把值得解释的术语挑出来，需要的时候在屏幕边上给出解释和提醒，不需要的时候保持安静。

做得慢的原因很简单：这类工具默认要一直听你说话，边界不写清楚，功能再多也不敢用。所以项目先定契约、门控和隐私边界，再接真实的采集与模型端点。

## 现在能做什么

- **实时转写**：系统音频环回（WASAPI）→ 16 kHz 单声道 → vosk 流式识别。半句实时刷新，稳定句进全文缓冲，超时强制收句后自动接回上一行，不会把一句话读成两行。
- **按需出卡**：默认不自动出卡。选中一段文字查意思，再生成卡片；也可以在设置里打开自动出卡，打开后有限流（同词 90 秒、每分钟 8 张）。
- **选中查义**：配了模型 Key 就调模型，没配就退回本机上下文（出现次数、相关句子），面板上标明结论来源。
- **联网查证**：博查、Tavily 两家预设，只发选中的 80 字以内，默认每小时 20 次，可清 Key、可改限额。
- **AI 提醒 / 怎么回**：看最近 12 句上下文，给两条提醒和一两句能直接说出口的回应，窗口大小可调。
- **隐私**：投屏拒卡、紧急遮蔽、凭据进系统凭据管理器、业务载荷字段级 AES-256-GCM、审计只追加。

界面只有工作页和设置页。开会要按的按钮都在工作页，配置项全部收进设置页。

## 还不能做什么

- 只支持 Windows，macOS 没有实现。
- 会议窗口的字幕通道读不到文本（腾讯会议、飞书的 UIA 元素为空），实际依赖系统音频；OCR 兜底默认关闭，未在真实字幕上验证。
- 投屏检测与紧急遮蔽目前只能通过开发期环境变量注入，系统层面没有自动侦测。
- 真机性能、误触发率、长时间多场会议的稳定性都还没数据；检索召回质量取决于所配服务。
- 不做会后纪要导出，转写全文只在内存里，退出即清空。

## 技术栈

- 桌面：Rust + Tauri 2（`app/src-tauri`，31 个 IPC 命令）
- 前端：React 19 + TypeScript + Vite（`app/`）
- 分层：`crates/domain`、`crates/application`、`crates/infrastructure`、`crates/platform-win`（WASAPI / UIA / OCR）、`crates/ui-bridge`
- 存储：SQLite，业务载荷字段级 AES-256-GCM；可选 `sqlcipher` 页级加密（FTS 索引需要该模式才能覆盖）

## 隐私原则

- 凭据不入库、不进日志、不进审计、不进回放。
- 日志只允许白名单字段，原文、完整地址、查询全文不落盘。
- 数据库打开前必须提供系统密钥库引用与派生密钥，不允许明文口令或无密钥打开。
- 出网只有三处，全部由点击触发，且每次只发最小片段。
- 不内置 AGPL/GPL 组件，检索源通过开放 SPI 接入。
