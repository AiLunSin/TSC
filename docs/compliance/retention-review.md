# 审计归档保留期复核单（5 年，待法务确认）

> 追溯 SPEC 6.1-7、7.4.2 · DESIGN 2.7.4 · TASKS 附录 G（U-07-52）
> 状态：**待法务复核**；在签署前，代码保留 `retained`（待定）标记，对外不得宣称"5 年合规保留"。

## 1. 事实

| 项 | 现状 |
|---|---|
| 存储位置 | 使用者本机 SQLite（`meeting.db`）；可选 SQLCipher 页级加密 |
| 审计字段 | `action`、`actor`、`occurred_at`、`target`、`summary`、`prev_hash`、`self_hash` |
| 内容边界 | 不含发言原文、卡片标题/结论、查询原文、URL、页面正文、参会人信息；`summary` 限 200 字符且经运行时零转录扫描 |
| 完整性 | SHA-256 哈希链；每 1,000 条锚点；UPDATE 无条件拒绝，未归档 DELETE 拒绝 |
| 在线保留 | 180 天（SPEC 6.1-7） |
| 归档保留 | **暂定 5 年**；按自然月封存为 AES-256-GCM 包，AAD 绑定月份与首末记录；归档后移出在线表 |
| 删除能力 | 会话删除 1 分钟内完成（不含审计摘要）；已归档审计记录**不支持单条删除**，仅能整包销毁 |
| 传输 | 无云端上传；归档包留在本机 |

## 2. 待确认问题

1. **必要性**：个人自用、本地存储场景下，180 天在线 + 5 年归档是否均属"最小必要"？是否存在更短且足够追溯的期限。
2. **删除权与不可篡改的冲突**：使用者要求删除某次会议时，对应审计摘要是否必须一并从归档包中删除？若必须，需破坏"只追加 + 哈希链"设计，改为"逻辑删除 + 链保留"并接受可验证性下降。
3. **告知义务**：是否必须在隐私说明与设置页展示"审计在线 180 天、归档 5 年、归档不可单条删除"。
4. **密钥丢失**：归档密钥由本机 DPAPI 派生，设备损坏即无法解密；是否需在归档时提示"请自行备份"。
5. **未来形态**：若后续商业分发或接入组织管理员视图，是否需要重新做留存评估与跨境评估。

## 3. 可选裁决

| 选项 | 内容 | 代码影响 |
|---|---|---|
| A（推荐，个人自用） | 在线 180 天；归档 1 年；隐私说明明示"归档不可单条删除" | 改常量 `ARCHIVE_RETENTION_YEARS = 1`；补隐私文案 |
| B | 维持在线 180 天 + 归档 5 年 | 仅移除 `retained` 标记与文档口径 |
| C | 取消归档，仅保留 180 天在线审计 | 停用 `archive_due` 调度；删除归档表与相关测试 |
